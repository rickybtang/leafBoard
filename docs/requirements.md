# LeafBoard 产品需求 V1

## 1. 产品目标

将淘汰的 BOOX Leaf2 作为专用、常驻、可拼装的信息显示屏。不同数据生产端按照统一 JSON 协议独立发布卡片；Leaf2 选择卡片、尺寸、顺序和页面进行展示。

## 2. 运行边界

- Android App 正常情况下始终处于前台。
- App 使用应用级保持唤醒能力，不修改系统全局屏幕超时设置。
- 用户仍可通过系统 Home 或 App 的“返回系统”入口退出。
- 默认每 15 分钟检查一次数据；支持 1、3、5、10、15、30、60 分钟。
- 轮询不等于重绘：数据未变化时不下载卡片、不刷新屏幕。
- 支持用户配置夜间时段。V1 在夜间把 App 窗口亮度降至 0 并显示极简页面，进程仍保持前台，避免引入后台唤醒逻辑。
- 不以续航、烧屏或后台保活为 V1 优化目标。

## 3. 数据写入方式

V1 支持三条路径：

1. 自定义 Producer 把规范 Card JSON 提交给 macOS Hub，Hub 校验后发布到坚果云 WebDAV。
2. 开发阶段通过 ADB/USB 将 JSON 导入 Leaf2 本地目录。
3. macOS Hub 提供本机管理网页，可视化展示已保存卡片；原始 JSON 仅作为折叠的协议诊断。

macOS Hub 启动时只加载本地已有 Card，不读取任何预设业务数据源，也不立即发布；首次自动发布在完整配置间隔后执行，用户仍可随时手动执行“发布已保存卡片”。

所有路径必须先通过同一份 JSON Schema 校验。

## 4. 卡片和布局

- 卡片类型：`metric`、`list`、`status`。
- 卡片尺寸：`small`、`medium`、`large`。
- 小、中、大分别占用 1×1、2×1、2×2 网格，面积比例为 1:2:4。
- 卡片按顺序值升序排列，再按从左到右、从上到下寻找可放置位置；设置页使用从 1 开始且不重复的顺序值。
- 字段使用 `minSize` 表达可见性，保证小卡片字段包含于中、大卡片中。
- `metric` 和 `status` 卡片必须且只能定义一个 `role=primary` 字段，作为各尺寸中占最大视觉面积的“大字报”主信息。
- 大字报必须单行显示；动态文本没有稳定长度上界时，接入前确认短名称和最大样本，不以换行或静默截断兜底。
- 小卡片和中卡片标准密度均为一个主信息加最多三组详情；小卡片使用单行短标签和值，中卡片保留完整字段名和值。
- 大卡片保持与中卡片相同的主信息字号，详情增加到五至六行，并放大详情字段名和值的字号。
- 大卡片允许一行详情包含一个字段名和两个结构化值；三个槽位独立测量，来源侧提供短名称，Reader 负责数值压缩和本地化，字段之间不得覆盖。
- Leaf2 使用四列网格和分页展示；物理翻页键用于切页。
- 布局属于设备本地偏好，Producer 不得改变设备布局。
- 设置页必须列出已配置 Producer 的最后有效 Catalog 中全部有效 Card；不得维护写死的卡片名称清单，USB 开发导入卡片不进入正常云端布局清单。
- 不允许卡片携带 HTML、CSS 或 JavaScript。

## 5. Producer 边界

- 公共仓库不内置真实数据源，避免把维护者当前使用的服务变成所有用户的默认能力。
- `protocol/examples/quota-card.json` 只用虚构数值展示 Codex Card 的大致结构，不包含读取实现、账号、会话或真实额度。
- 用户通过项目 Skill 确认自己的稳定数据源，独立实现 Producer，并自行负责来源授权、revision 递增和失败语义。
- Hub 只接收、校验、缓存和发布 Card；Reader 只同步、缓存、布局和渲染。
- 时间类界面信息由 Leaf2 本地计算，不要求 Producer 每分钟发布。

## 6. 安全要求

- 坚果云账号和应用密码不得写入仓库、日志或卡片 JSON。
- macOS 凭证保存到 Keychain。
- WebDAV 密码只能由固定的 `LeafBoardCredentialHelper` 访问，不得进入卡片 JSON、日志或仓库。
- 自定义 Producer 的来源凭证由 Producer 自己安全保存，不得提交给 Hub 或写入 Card。
- 普通用户首次配置后，Keychain 授权最多出现一次；应用升级、重新构建主程序和移动工作区不得重复要求授权。
- 源码构建必须复用一次性创建的固定本地签名身份，避免重建后反复请求 Keychain 授权。
- Android 凭证保存到 Android Keystore 加密的本地配置。
- 建议使用专门的坚果云账号或至少使用独立应用密码和 `/leafboard/` 根目录。
- 每张卡片只能由一个 Producer 写入。

## 7. V1 验收标准

- 三份 Schema 能校验有效示例并拒绝关键无效输入。
- macOS Hub 的本机 API 能接收合规 Card，拒绝非法 Card，并保存最后有效 Card。
- macOS 应用能将卡片和 Catalog 发布到 WebDAV，且凭证不进入日志。
- macOS Hub 启动后菜单栏立即可交互，不因默认采集、外部验证或发布而阻塞；自动采集在完整配置间隔后开始。
- Leaf2 App 能从 WebDAV 拉取 Catalog 和变化卡片，离线时保留最后一次有效数据。
- Leaf2 App 能通过 ADB/USB 导入同格式卡片。
- Leaf2 App 支持选择卡片、尺寸、顺序、刷新间隔和夜间时段。
- App 前台时保持屏幕唤醒，数据不变时不重绘。
- 用户能退出到原 BOOX Home，卸载后不需要恢复系统配置。
- 首次配置允许出现一次 Keychain 授权；随后重新打包并重启 Hub 两次，均不得再次弹出授权窗口，且 WebDAV 发布成功。

## 8. V1 不做

- 不做 Root、Bootloader 解锁、桌面替换或系统分区修改。
- 不做后台 3 分钟保活、FCM、MQTT 或消息队列。
- 不做多写入者自动合并。
- 不做任意网页组件、远程脚本或自定义 CSS 渲染。
- 不接入未确认接口的额度、待办和快递来源。
